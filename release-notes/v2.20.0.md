# Snacks v2.20.0

**Automated Media Library Transcoder**

This release keeps your Arr apps in step with what Snacks writes. **Lidarr** joins Sonarr and Radarr as a connection, and when an encode **replaces its original**, Snacks now asks the owning app to rescan just that series, movie, or album folder so the new file is imported instead of showing as missing. Music placement gets the same in-place replacement model video has had — including on cluster encodes, which previously ran music through the *video* placement settings. Plex and Jellyfin rescans only consider libraries of the file's kind, Jellyfin requests use the authorization header current Jellyfin accepts, and the Sonarr/Radarr folder-name fallback no longer stumbles on directory names containing a dot.

---

## Lidarr connection

**Settings → Connections → Lidarr**: enable, base URL, API key, and a **Test** button that hits `/api/v1/system/status` (Lidarr speaks API v1; Sonarr and Radarr stay on v3). `IntegrationConfig.Lidarr` is an `ArrIntegration` like the other two, so the `SNACKS_INTEG_Lidarr__BaseUrl` / `__ApiKey` / `__Enabled` environment overrides lock it the same way. Lidarr's only job is the master's post-replacement album rescan, so the cluster's `GET /api/cluster/integrations` handout to workers omits it.

## Sonarr, Radarr & Lidarr rescans after a replacement

The Arr apps track individual files. An episode, movie, or track whose original Snacks replaced — `Movie.mp4` → `Movie.mkv`, or a smaller file under the same name — reads as missing or stale until the app rescans its folder. With the connection enabled, Snacks requests that rescan itself (**`IntegrationService.QueueArrRescan`**, new).

| App | What is rescanned | Command |
| --- | --- | --- |
| Sonarr | The one series that owns the replaced episode | `RescanSeries` with `seriesId` → `POST /api/v3/command` |
| Radarr | The one movie that owns the replaced file | `RescanMovie` with `movieId` → `POST /api/v3/command` |
| Lidarr | The album folder of the replaced track | `RescanFolders` with that folder and `addNewArtists: false` → `POST /api/v1/command` |

### When it fires
Only when a kept output **replaced its original**: **Replace Original Files** for video, **Delete original file after success** for music (**`ReplacesOriginal`**, new — music reads its own toggle, never video's). Keep-both encodes and no-savings outcomes send nothing. All three completion paths are wired — local video, local music, and the master's post-download `HandleRemoteCompletion` — and only the master ever contacts an Arr; workers never do.

### Finding the owner
- **Music** maps the track's path onto Lidarr's root folders (`GET /api/v1/rootfolder`, cached ten minutes) with the same trailing-segment anchor matching the Plex/Jellyfin rescans use, then takes the parent directory in Lidarr's own separator style — a `D:\Media\Music` root yields `D:\Media\Music\Artist\Album`.
- **Video** uses the Sonarr series list or Radarr movie list with each entry's folder as a root. `MediaTypeDetector.Classify` decides who is asked first (SxxEyy naming → Sonarr, otherwise Radarr); the other is tried when the first has no match, so a pilot without episode numbering still finds its series. When two entries share a folder name (`/tv/Show (2020)` and `/anime/Show (2020)`), the one whose deeper path lines up with Snacks' path wins.
- **No match, no scan.** Unlike Plex/Jellyfin there is no library-wide fallback — an unmatched path isn't in the Arr anyway, and a full scan per encode would be heavy on large libraries. The log records *"No Sonarr series or Radarr movie matched '…'; skipping rescan"*.

### One command per season or album
Requests are debounced per `{app}|{baseUrl}|{series, movie, or folder}` and sent once the scope has had no replaced file for **30 seconds** (`RescanQuietPeriod`), so a batch of episodes or a whole album becomes one command. The Arrs fold a duplicate command into one that is already queued *or running* and answer with that command's id; if Snacks gets its previous id back as `started`, the running scan may have listed the folder before this file landed, so the request is **re-armed** for a fresh scan once the scope is quiet again (bounded at five re-arms). A new id reported as `started` is just the Arr picking the job up quickly and is left alone; a response without an id is never treated as merged.

### Radarr keeps the movie monitored
With **Unmonitor Deleted Movies** on, Radarr unmonitors a movie the moment the rescan finds its old file missing — even though the same scan imports the replacement. Snacks reads the movie's `monitored` flag before posting the command, polls `GET /api/v3/command/{id}` every two seconds (up to five minutes; three consecutive read failures end the wait, scattered ones do not) and, if the scan flipped a monitored movie off, switches it back on through `PUT /api/v3/movie/editor` with only `movieIds` and `monitored` in the body. Radarr's own scheduled rescans get no such correction. Sonarr needs none: it defers that decision until after the scan and drops any episode that was re-imported meanwhile.

### One catalogue, two consumers
The Sonarr/Radarr series and movie lists now live in a single cache (**`GetArrCatalogAsync`** / `ArrCatalogEntry`, replacing `_arrLangCache`) that feeds both the original-language lookup and the rescans, keyed by provider, URL, and key with the ten-minute TTL. A failed fetch is still negative-cached for three minutes and now suppresses rescans as well as language lookups; saving the connection settings clears it.

## Music placement: replace in place

`ConvertMusicAsync` used to write `Track [snacks].m4a` into the music output directory (or beside the source) and, with **Delete original file after success** on, delete the source and leave the tagged file where it was. It now hands the validated output to the same placement step video uses, and **`HandleMusicOutputPlacement`** (new) applies the *music* settings:

| Music settings | Result |
| --- | --- |
| **Delete original file after success** on | The output drops its `[snacks]` tag and replaces the source in the source's folder under the source's name via `ReplaceOriginalAsync` (park the original as `.snacks.bak`, move the encode in, delete the backup, restore on failure). `Track.mp3` → `Track.mp3` overwrites the source path. A music output directory only holds the encode until then. |
| Off, output directory set | The tagged file is kept in the music output directory; the original stays. |
| Off, no output directory | The tagged file is kept beside the untouched original. |

Either way an output staged elsewhere — a cluster download lands in the master's encode or video output directory — is moved into place. The video **Replace Original Files** toggle and video output directory never decide where an audio file lands or whether its source survives.

**Cluster fix:** the master's `HandleRemoteCompletion` always ran the *video* placement path, so a cluster music encode obeyed the video replace toggle and the video output directory. Workers now skip placement entirely (`ConvertMusicAsync(…, skipPlacement: true)` from `ConvertMusicForRemoteAsync`), keeping the tagged output where the `*[snacks]*` glob finds it, and the master places it after download under the music settings.

### Upgrade notes
- If you run music with **Delete original file after success** on, replaced tracks now appear under their original name in the album folder, not as `[snacks]`-tagged files in the music output directory. This is what Lidarr, Plex, and Jellyfin expect, but it is a change from 2.19.
- A music placement failure now fails the job (as video does) instead of being logged while the job completes.
- A replaced track is an ordinary library file on the next scan. The default **Skip files already in target codec** rule (with its bitrate tolerance) keeps it from being queued again; with that rule off, a replaced track is eligible for another pass.

## Plex & Jellyfin rescans know what kind of file finished

`TriggerRescansAsync` takes the item's `MediaKind`, and `LibraryRoot` now carries the library's content type (Plex section `type`, Jellyfin `CollectionType`). **`RootsForKind`** (new) narrows the roots a file can live in:

- **Music** maps only onto music libraries (Plex `artist`, Jellyfin `music`). A movie library whose `/data/media` root happens to share a `media` segment with the track's path no longer wins and refreshes a folder that isn't there.
- **Video** maps onto everything else; a mixed Jellyfin library that reports no `CollectionType` counts as video.
- A server that lists libraries but **none of that kind is skipped** (*"Plex: no music library; skipping rescan for '…'"*) instead of fully refreshed per file — before, every music track asked a video-only Plex to rescan every library.
- A failed library lookup, or a library of the right kind that doesn't line up with the path, still falls back to the full refresh as before.

**Plex scoped refresh keeps Plex's separators.** The scoped `refresh?path=` directory was computed with `Path.GetDirectoryName`, which applies the Snacks host's rules: on Windows it rewrote `/data/movies/X` to `\data\movies\X` (a Linux Plex answers 200 and scans a folder that doesn't exist), and on Linux it found no parent in a `D:\…` path at all and refreshed the whole section. **`ParentDirectory`** (new) trims in the remote server's own style; `GetDirectorySafe` is gone.

**Jellyfin authentication.** Every Jellyfin request (`/System/Info`, `/Library/VirtualFolders`, `/Library/Media/Updated`, `/Library/Refresh`) now sends `Authorization: MediaBrowser Token="…"`. Current Jellyfin ships with legacy authorization disabled and answers the old `X-Emby-Token` header with 401; the `Authorization` form works on current and older releases alike (**`AddJellyfinAuth`**, new).

## Original-language folder fallback

The Sonarr/Radarr fallback that matches a file's folder names against the catalogue when the Arr's path doesn't prefix the local path applied `GetFileNameWithoutExtension` to *every* segment, so `Mr. Robot (2015)` was compared as `Mr` and never matched. Only the file name loses its extension now (the flat `Movies/Title (year).mkv` layout still works); directory names are compared whole.
